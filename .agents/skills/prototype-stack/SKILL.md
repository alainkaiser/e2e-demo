# Prototype stack

Use what is installed. Install a package only when nothing installed covers the need, and then the one this table names.

| Need | Use | Read |
|---|---|---|
| Pages, links, URL and search params, page data | React Router 8 in framework mode, rendering in the browser | the `react-router` skill |
| Button, text field, select, dialog, popover | `~/components/ui/` | the component files |
| Other UI parts: menu, tabs, tooltip, accordion, drawer, combobox, checkbox, radio, switch, slider | Base UI, wrapped in a new `~/components/ui/<name>.tsx` styled like the existing ones | `node_modules/@base-ui/react/docs/react/components/<name>.md` |
| Styling | Tailwind CSS 4 utilities with the tokens in `app/app.css` | |
| Font | Geist Variable, self-hosted through `@fontsource-variable/geist`, imported in `app/app.css`. For a customer's font, install its `@fontsource-variable/<name>` package, or put its `.woff2` files in `public/fonts/` with an `@font-face` rule, then change `--font-sans`. Self-host every font, so pages load nothing from other servers | [fontsource.org](https://fontsource.org) |
| Icons | `lucide-react`, for example `import { CalendarDays } from 'lucide-react'` | [lucide.dev/icons](https://lucide.dev/icons) |
| Feedback after an action | `sonner`: `toast.success('Appointment booked')`; `<Toaster>` is already in `app/root.tsx` | |
| Animation | CSS transitions; `motion/react` for exit animations, layout changes, springs and drag | |
| Simple form | `Form`, `Field`, `FieldLabel`, `Input`, `FieldError` from `~/components/ui/field`: browser validation, errors show on submit | |
| Form with rules across fields, steps or fields that depend on each other | TanStack Form with a zod schema, rendered with the `Field` parts | `node_modules/@base-ui/react/docs/react/handbook/forms.md`, section "TanStack Form" |
| Data shapes, checking input or API answers | zod 4: `import { z } from 'zod'` | |
| Table with sorting, filtering or paging | TanStack Table 9 (`@tanstack/react-table`) | its skills in `node_modules/@tanstack/react-table/skills/`, starting with `getting-started`, and in `node_modules/@tanstack/table-core/skills/` |
| Chart | TanStack Charts (`@tanstack/charts`, React component from `@tanstack/charts/react`) | its skills in `node_modules/@tanstack/charts/skills/`, starting with `design-a-chart` |
| Money, dates, times | `formatChf`, `formatDate`, `formatTime` from `~/lib/format` | |
| A real API with an OpenAPI description | a typed client generated by `@hey-api/openapi-ts` (install it as a dev dependency), called in a route's `clientLoader` | [heyapi.dev](https://heyapi.dev) |
| Many API calls with caching on one page | TanStack Query (`@tanstack/react-query`) | |
| Several languages | `react-intl`, as in Sitewerk's production apps | |
| Tests for logic | Vitest | |

## Pitfalls

- Base UI composes with the `render` prop, never `asChild`: `<DialogTrigger render={<Button />}>Open</DialogTrigger>`. Popups nest `Portal`, `Positioner` and `Popup`.
- Base UI's examples use `neutral-*` colors and `dark:` variants. Translate them to the tokens and drop `dark:`.
- `framer-motion` is the old name of motion, and `@tanstack/react-charts` is TanStack Charts' old package. Use `motion/react` and `@tanstack/charts`.
- Made-up data goes in `app/data/<topic>.ts` with a TypeScript type, read by pages directly or through a `clientLoader`.
